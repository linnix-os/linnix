# Verifying Linnix Releases

Every tagged release and every container image pushed from this repository
carries a Sigstore-backed build provenance attestation, generated by GitHub
Actions (`actions/attest-build-provenance`). An attestation proves that an
artifact was built by this repository's workflow, from a specific commit, and
has not been modified since.

## Release assets (tarballs, .deb, .rpm, SBOMs)

Each release contains:

| File | What it is |
|---|---|
| `linnix-<arch>-unknown-linux-gnu.tar.gz` | `cognitod`, `linnix-cli`, eBPF object |
| `cognitod_<ver>_<arch>.deb`, `cognitod-<ver>.<arch>.rpm` | OS packages |
| `cognitod-<arch>.cdx.json`, `linnix-cli-<arch>.cdx.json`, `linnix-ai-ebpf-<arch>.cdx.json` | CycloneDX SBOMs of the Rust dependency tree, one per shipped binary |
| `SHA256SUMS` | Checksums for all of the above |

Verify with the GitHub CLI (no key management needed):

```bash
gh attestation verify cognitod_0.3.0_amd64.deb --repo linnix-os/linnix
gh attestation verify SHA256SUMS --repo linnix-os/linnix
sha256sum -c SHA256SUMS --ignore-missing
```

Attestations can also be checked offline: download the bundle with
`gh attestation download` and verify it with `cosign verify-blob-attestation`
or `gh attestation verify --bundle`. See the
[GitHub artifact attestation docs](https://docs.github.com/en/actions/security-for-github-actions/using-artifact-attestations).

## Container images

`ghcr.io/linnix-os/cognitod` and `ghcr.io/linnix-os/llama-cpp` are attested
by digest. BuildKit also attaches its own SLSA provenance (`mode=max`) and an
SPDX SBOM to the image index.

```bash
gh attestation verify oci://ghcr.io/linnix-os/cognitod:<tag> --repo linnix-os/linnix

# BuildKit SBOM / provenance
docker buildx imagetools inspect ghcr.io/linnix-os/cognitod:<tag> --format '{{ json .SBOM }}'
docker buildx imagetools inspect ghcr.io/linnix-os/cognitod:<tag> --format '{{ json .Provenance }}'
```

Pin images by digest (`@sha256:...`) in production, not by tag.

## Known gaps

- The BuildKit image SBOM lists Debian packages, not the Rust crates compiled
  into `cognitod`. Use the release `.cdx.json` files for the Rust dependency
  tree.
- Releases are not yet reproducible bit-for-bit.
- `cargo deny check` (licenses, advisories, sources) runs on every PR in CI.
  Image vulnerability scanning is not yet part of the release workflow.
